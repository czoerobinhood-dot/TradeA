# A股全市场形态筛选器

这个项目使用 AkShare 获取沪深京全A股实时快照、前复权日线和四档资金流，在全市场中寻找严格的低位资金博弈形态。默认先让全部非 ST/退市 A 股经过同一套宽松快照门槛，再对通过者读取完整日线精筛；不再按人气榜前80只截断。

它输出的是待人工复核的研究候选，不是自动交易信号。接口失败、字段变化或历史不足都会出现在报告的“数据问题”中，不会被静默解释成低分。

当前筛选数据源是 AkShare 封装的腾讯和东方财富公开接口，不是华泰证券。华泰专业版作为游客行情与人工复核终端使用；客户端本地行情文件属于专有格式，当前版本不把它们冒充为已接入的数据源。

## 数据与规则

- 全市场快照：`stock_zh_a_spot_tx`，失败时回退 `stock_zh_a_spot_em`
- 可选热点模式：`stock_hot_rank_em`、`stock_board_concept_name_em`、`stock_board_concept_cons_em`
- 前复权日线：`stock_zh_a_hist`
- 四档资金流：`stock_individual_fund_flow`
- 已确认日K参考样本：光迅科技、金健米业、敦煌种业、金牛化工、天融信、深中华A、粤传媒、北陆药业、大金重工、海峡创新、金辰股份等
- 缺口平台样本：平潭发展（仅校准缺口趋势，不覆盖第一门槛）

AkShare 是数据接口库，不是预测模型。本项目在数据之上检查：

1. 高位至低点回撤是否在35%-65%，中心目标约50%。
2. 当前是否仍处于底部：低点后反弹不超过35%，并且仍比该轮高点低至少20%。
3. 日K底部红量是否得到确认：底部阶段出现放量，最近20个日K中红色上涨K线成交量占比至少60%，并至少出现2根红色放量柱。
4. 股价是否尚未大涨：单日不超过8%、5日不超过12%、20日不超过15%，高于20日线不超过10%，且当前没有封板。
5. 近120日涨跌停活动、近期换手和资金四线是否提供额外确认。
6. 第二层优选是否出现近期向上跳空、收盘不回补、缺口上方横盘、向上趋势和缺口后持续放量。

缺口趋势默认检查最近25个交易日，缺口至少1.2%，至少横盘3个交易日，收盘区间振幅不超过18%，缺口后成交量中位数至少为缺口前的1.3倍。盘中下影线进入缺口与收盘有效回补会分别记录。该层只影响通过第一门槛股票的排序；“缺口趋势”分组会显示全部达到近似条件的股票，并保留“已涨停、已启动、不符合”等原结论，进入该分组不等于成为推荐候选。平潭发展自身第一门槛不通过，因此不会因缺口形态重新成为候选。光迅科技的新缺口会先显示为“等待横盘确认”。

资金博弈部分使用超大单、大单、中单和小单的每日净流入占比，先做3日指数平滑，再计算5日滚动和。它是公开数据构造的代理线，**不等同于东方财富客户端截图中的专有指标公式**。

红绿成交量柱按日K的收盘价与开盘价着色：收盘不低于开盘记为红量，否则记为绿量。红量占优可作为上涨日成交活跃的代理，但成交本身由买卖双方撮合，不能把红柱直接解释成真实主动买单；精确主动买卖需要逐笔或Level-2数据。

“当前价、当前涨跌幅、今日是否涨停”优先使用全市场实时快照；回撤、量能、均线和历史涨跌停仍使用前复权日线。这样即使日线接口只更新到上一交易日，当天已经封板的股票也会进入“已启动/错过低位”，不会继续混在尚未涨停候选中。报告同时保留涨停前的价格条件快照，便于说明它为何曾经入选。

日线默认读取东方财富；若该端点连接失败，沪深股票自动回退到 AkShare 的腾讯前复权日线 `stock_zh_a_hist_tx`。实际来源会写入 CSV、JSON 和 HTML。热点概念与四档资金流没有等价备用数据时保持缺失，程序按可用评分项重算权重，并降低数据完整度。

全市场快照会先排除不支持的代码、ST/退市和无有效价格股票。普通股票默认要求快照换手率4%-20%、量比至少1.0，且5/20/60日涨幅不超过20%/15%/20%；当前涨停股票使用0.5%-40%的独立换手通道。门槛可在 `universe_prefilter` 中调整。设置 `universe_mode` 为 `hot` 可恢复旧热点候选模式。

## 安装

需要 Python 3.11 或更高版本。当前锁定并核对的是 AkShare `1.18.96`。

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[test]"
```

## 启动手动刷新服务

```powershell
.\run.cmd
```

终端出现 `选股器已启动: http://127.0.0.1:8765/` 后，在浏览器打开该地址。后台定时刷新默认关闭；查看或刷新报告页不会自动启动新扫描。需要更新时点击页面右上角“重新扫描”，完成后页面会自动显示新报告。扫描失败时继续保留上一版报告。

本地交互页面统一使用 [http://127.0.0.1:8765/](http://127.0.0.1:8765/)。不要长期启动 `8770` 或其他端口的 `site` 静态预览；`site/index.html` 仅用于 Cloudflare 只读发布，更新它时运行 `export_pages.cmd`。

页面上的“重新扫描”会主动忽略有效缓存并执行一次完整刷新。服务运行时也可以从另一个 PowerShell 主动调用同一条受锁保护的刷新路径：

```powershell
Invoke-WebRequest http://127.0.0.1:8765/refresh -UseBasicParsing | Out-Null
```

只有明确需要恢复定时更新时，才传入刷新间隔秒数：

```powershell
.\run.cmd --refresh-interval 300
```

30 秒内的普通页面重复刷新会复用刚生成的结果，不会创建并发扫描。

[http://127.0.0.1:8765/](http://127.0.0.1:8765/)

如果 PowerShell 允许脚本，也可以运行：

```powershell
powershell.exe -ExecutionPolicy Bypass -File .\run.ps1
```

停止服务：回到启动服务的终端，按 `Ctrl+C`。

## Cloudflare 部署边界

当前扫描器依赖 Python、Pandas 和 AkShare，不能直接作为 Cloudflare Pages 或 Workers 的动态后端运行。后续接入 Cloudflare 时，建议在以下两种方式中选择：

- 公开只读报告：在可信主机定时扫描，将生成的 `latest.html` 发布到 Cloudflare Pages。访客只能看报告，不能触发扫描。
- 私有扫描服务：在常驻主机运行本项目，通过 Cloudflare Tunnel 暴露，并使用 Cloudflare Access 保护整个站点。

不要在未加访问控制时公开“重新扫描”入口，否则任何访问者都能触发耗时的全市场抓取。详细准备事项见 [Cloudflare 接入说明](docs/CLOUDFLARE.md)。

当前生产站点是 [https://tradea-3al.pages.dev/](https://tradea-3al.pages.dev/)，采用 Direct Upload。它没有连接 GitHub 自动部署，也不会主动运行扫描。项目统一采用“一份报告、两个运行外壳”：

首次创建管理员和迁移本机收藏见 [TradeA 成员初始化教程](docs/INITIALIZATION.md)。

| 项目 | 本地 `8765` | Cloudflare Pages |
|---|---|---|
| 报告来源 | `reports/latest.html` | 由同一文件导出的 `site/index.html` |
| 扫描 | 可手动点击“重新扫描” | 禁止触发扫描 |
| 收藏 | 存在 `%LOCALAPPDATA%\TradeA\owner.vars` 时自动使用主管理员 D1 共享收藏；否则使用浏览器本地收藏 | 未登录时本地收藏；登录后 D1 共享收藏 |
| 标注与训练反馈 | 回环地址启动时由服务端自动建立主管理员会话 | D1 成员标注、管理员审核后导出 |
| 版本核对 | 报告生成时间与 SHA-256 | `site/release.json` 与线上回读 |

生成 Pages 只读发布目录：

```powershell
.\export_pages.cmd
```

该命令读取 `reports/latest.html`，生成 `site/index.html`、`site/_headers` 和 `site/release.json`，然后立即校验报告时间、源文件 SHA-256、只读边界和成员前端文件。静态版本会移除扫描入口，但保留排序、筛选、本地收藏和云端成员协作。

通过 `run.cmd` 在固定入口 `127.0.0.1:8765` 启动时，如果非同步目录 `%LOCALAPPDATA%\TradeA\owner.vars` 存在，本地服务会在服务端读取主管理员账号和密码，连接生产成员 API，并自动核验 `admin` 角色。服务不会读取项目根目录或 OneDrive 中的 `.owner.vars`；`LOCALAPPDATA` 不可用时自动登录直接禁用，不会回退到项目目录。凭据和云端 Cookie 不会发送给浏览器；成员 API 严格校验固定 Host、同源来源和浏览器 Fetch Metadata，并禁止页面被其他网站嵌入。登录、初始化和退出接口在本机自动登录模式下被禁用，防止网页替换主管理员会话；服务关闭时会注销云端会话。若凭据文件或成员前端文件不存在，报告仍可使用，但成员功能不会启用。管理员页面中的收藏、标注、成员和审核操作直接作用于生产成员数据库。

首次准备发布工具：

```powershell
npm install
```

完成本地扫描并人工确认报告后，统一发布：

```powershell
.\publish_pages.cmd
```

发布命令不会重新扫描或修改 `reports/latest.html`。它依次导出当前报告、运行 Pages/D1 与 Worker 测试、Direct Upload 到 `tradea` 项目，再从生产地址回读 `release.json`、首页和成员 API。任一步失败都会停止，不能把仅有 Wrangler 成功提示视为验收通过。

## 单次扫描

不启动网页服务，只运行一次并更新报告：

```powershell
.\scan.cmd
```

单次扫描常用参数：

```powershell
.\scan.cmd --top 10 --refresh
.\scan.cmd --offline
```

或者直接运行：

```powershell
.\.venv\Scripts\python.exe -m ashare_screener scan --config config.example.json --output reports --top 20
```

常用选项：

```text
--refresh         忽略有效缓存，重新抓取
--offline         只读取本地缓存，不访问网络
--no-concepts     热点模式下停用概念板块
--no-fund-flow    停用四档资金流代理
--as-of 日期      指定历史数据截止日，格式 YYYY-MM-DD
```

每次扫描生成：

- `reports/latest.html`：可视化复核报告
- `reports/scan_*.csv`：候选排序表
- `reports/scan_*.json`：完整机器可读结果、模板和失败项

## 搜狐交叉校验

搜狐证券可以作为独立校验源接入。当前实测可用的是其行情页面内部日线接口：

```text
https://q.stock.sohu.com/hisHq?code=cn_000592&start=20260901&end=20260918&stat=1&order=D&period=d&rt=json
```

接口返回日期、开盘、收盘、涨跌额、涨跌幅、最低、最高、成交量、成交额和换手率。它返回的是未复权日线，响应标记为 `application/x-javascript; charset=gbk`，没有四档资金流字段，也不应视为有稳定性承诺的官方开放 API。因此它不替换现有东方财富/腾讯前复权主链，只用于检查最近共同交易日的数据是否一致。

运行最新报告的交叉校验：

```powershell
.\audit_sohu.cmd
```

默认校验报告前20只，并额外包含光迅科技和平潭发展；逐日比较最近10个共同交易日的日期、OHLC、换手率、成交量单位和缺口结论。结果写入：

- `reports/source_audit_*.csv`
- `reports/source_audit_*.json`

可扩大抽查数量或共同交易日数：

```powershell
.\audit_sohu.cmd --limit 50 --compare-days 20
```

`confirmed` 只表示指定样本和区间内逐项一致，不代表全部股票、全部历史日期、实时性或资金流完全可靠；`partial`、`mismatch`、`error` 都需要人工查看明细。
命令仅在全部记录均为 `confirmed` 时返回成功退出码；任一记录未确认都会返回非零，便于自动检查发现异常。

HTML 报告顶部会显示全市场数量、快照通过数量和有效日线数量。候选排名表展示全部日线精筛结果；为控制文件体积，K线和资金图只展开前 `report_limit` 只（默认30）。表格支持分组、“右侧放量”和“缺口趋势”筛选，并可点击任意表头切换升降序。“全部”及其他普通筛选显示原有的通用逐股复核；点击“缺口趋势”则跨主结论分组列出全部近似形态，并把下方图表切换为独立的“缺口趋势详细复核”。两套复核内容同时保留但不会堆叠显示，切回“全部”会恢复通用逐股复核。缺口专属卡会明确展示缺口区间、回补状态、横盘确认、趋势条件和缺口后量能；同时进入两套复核的股票会分别提供“通用复核”和“缺口详解”两个入口。行内仍明确显示是否已涨停、已启动或不符合。当前状态、当前涨幅、右侧量比、缺口日期与幅度、缺口回补情况、横盘天数、缺口后量能和实时行情时间都会写入 CSV、JSON 与对应复核区。右侧量比及缺口趋势都是优选项，不作为一票否决条件。

点击候选表或逐股复核标题旁的星标可收藏/取消收藏股票；“收藏”筛选只显示当前报告中已收藏的股票。收藏代码保存在当前浏览器的本地存储中，刷新页面或重新扫描后仍会恢复，不会上传到第三方。

“本页K线”只负责滚动到当前报告的逐股复核区。页面会在完成定位后移除 `#stock-代码` 锚点，恢复干净地址；该锚点从来不代表收藏状态。未登录时收藏仅属于当前浏览器，成员登录后才切换为 D1 云端收藏。

股票名称可直接打开搜狐证券，查看日/周/月K线、盘口、财务、公告和公司资料；每行还提供“东财K线/F10”，用于查看指标K线、资金流、F10、公告和市场讨论。两站均已核对沪深京股票链接，其中东方财富的北交所链接使用 `/bj/<代码>.html`。另有“复制代码”按钮，便于在华泰客户端直接输入六位代码复核。

## 评分解释

默认总分由以下可用部分重新加权：

| 部分 | 权重 |
|---|---:|
| 当前人气 | 10% |
| 热点概念 | 5% |
| 技术形态 | 35% |
| 日线路径相似度 | 10% |
| 资金博弈代理 | 40% |

报告结论分为“严格匹配、接近标准、待资金数据、已启动/错过低位、数据不足、不符合”。进入前三类前必须同时通过“高位回落后仍在底部、底部放量确认、股价尚未大涨”三项价格门槛；总分不能绕过这些门槛。“待资金数据”表示价格侧已通过，但四档资金流尚未确认。华金资本、龙头股份这类当前已经明显上涨或封板的股票会进入“已启动/错过低位”。

## 局限

- 全市场行情和资金流来自第三方网页接口，可能限频、临时不可用或修改字段。
- 全市场模式是“全部股票快照初筛 + 通过者完整日线精筛”；未通过快照门槛的股票不会下载300日日线。首次扫描通常需要数分钟，后续会复用缓存。
- 北交所已纳入候选，但腾讯没有北交所历史日线备用源；东方财富不可用时会标记数据不足。
- 实时资金流失败时可以使用最近成功缓存，报告会明确显示，不会冒充实时数据。
- 参考样本由人工确认或已上涨股票产生，天然存在选择偏差和幸存者偏差；当前只比较日K路径，相似度只能描述形状，不能证明未来收益。
- 四档成交单分类不等于机构身份，资金代理只能辅助确认。
- 当前版本没有完成全市场负样本、交易成本和样本外回测，因此不能把分数解释为胜率。

下一阶段若要评价有效性，应固定规则和日期，对当时全部全市场初筛候选进行逐日留档，再统计5日、10日和20日收益、最大回撤及未上涨样本。
