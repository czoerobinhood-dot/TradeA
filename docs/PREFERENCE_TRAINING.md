# 日K偏好校准

本功能学习用户偏好的日K形态，采用冻结案例近邻比较，不预测上涨概率。
2026-09-20 的 v2 版使用用户明确认可的 7 只云端共享收藏：夏厦精密、青岛金王、北玻股份、道明光学、海看股份、德力佳、振江股份。
这些样本改为 `user_confirmed`，置信度为 1.0；将来未经确认的普通收藏仍为 0.5。收藏不被当作上涨正标签；未收藏股票也不被当作负标签。
顺络电子 002138 经用户确认不够理想，从正向参考移除，原因保留在新清单的 `excluded_samples`；不因此把它当成未来会跌的负标签。原 8 样本清单、v1 冻结模型和验证文件保留，不覆盖。
原收藏时的形态日期未知，所以收藏样本采用本次导入时最近交易日 2026-09-18，明确不回填为原收藏日。

每个样本冻结截止观察日的最近 90 个有效交易日，比较 90/40/20 日收盘路径、相对量能和日K红量占比。
价格路径保留涨跌幅度，成交量按自身中位数归一化。红量是收盘高于开盘的成交量，不等于真实主动买单。
样本清单、冻结模型与版本归档在被 Git 忽略的 `.cache/preferences/`；模型有内容 SHA-256，缺失或校验错误时会停用偏好层并显示数据问题。

防止少量样本过度影响选股：

- 按股票去重；排除候选自身，只取 3 只不同股票共同评分。
- 样本不使用观察日后的行情，也不按未来上涨幅度反选起点。
- 参考不能晚于候选实际行情日期；模型在实际导入日前停用。
- 固定窗口、尺度和权重，本轮未在这 8 个样本上搜索参数。
- 用 `有效置信度 / (有效置信度 + 8)` 收缩影响，理论调分上限 ±2 分；当前 3 个邻居下会远低于这个上限。
- 原价格硬条件和分类先执行。只有低位红量且未大涨的合格候选可调分；已启动、不符合及数据不足股票仅展示偏好分。
- 用户要求优先展示已认可形态，因此增加独立的名次策略：先比较原结论、低位红量状态、通过条件数，再比较基础综合分的固定 10 分档；同档内按形态相似度的固定 10 分档优先，同形态档继续按总分排序。相似度低于 60 为中性档。基础综合分档限制了可交换股票的基础分差小于 10 分，但不保证资金子分相近，验证报告单独列出资金分差。
- 名次策略只在至少 3 个不同的 `user_confirmed` 邻居、置信度均为 1、策略版本匹配且行情有效时启用。没有偏好数据或未经确认的样本不会继承上一轮优先级。页面标注“形态优先”。
- ±2 限制的是辅助总分，不能理解为名次影响也被它限制；新增名次策略的影响单独验证，不对这批样本搜索分档边界。
- 原启发式相似度保持独立，历史最佳上涨片段不作为本次偏好验证的证据。

复现本次校准（只读已有行情缓存，不扫描、不部署）：

```powershell
.\.venv\Scripts\python.exe -m ashare_screener train-preferences --config config.example.json --samples .cache\preferences\samples_20260920_confirmed.json --output .cache\preferences\model.json --validation reports\preference_validation_20260920_confirmed.json --baseline reports\scan_20260920_161208.json --as-of 2026-09-20 --offline
```

`config.example.json` 的 `preference_model_path` 指向模型；设为 `null` 可关闭偏好层。
网页仍由 `run.cmd` 启动，手动点击“重新扫描”才会生成新报告。收藏变化不会偷偷训练或覆盖冻结样本；后续明确提供的新案例再记录日期、重建版本并重复检查。

验证报告记录留一股票形态评分、未参与学习的候选对照、逐一删除样本后的调分和前 20 名变化。禁用偏好的基线同时关闭辅助调分和优先级，与旧 8 样本报告的顺序比较单独列出；同时记录最大名次变动、发生换位的基础分/资金分差、固定 ±1 相似度扰动下的敏感性。
这只是形态与稳定性验证。当前没有成熟的时间外收益区间和完整的负标签，不提供胜率、收益改善或“已证明泛化”的结论。
将来评估收益时应按真实观察日期向前走，并隔离同股票、重叠窗口及标签未来区间；不能用当前热点快照倒算历史候选。

方法依据：[scikit-learn 数据泄漏说明](https://scikit-learn.org/stable/common_pitfalls.html) 和 [分组、时间序列验证说明](https://scikit-learn.org/stable/modules/cross_validation.html)。
